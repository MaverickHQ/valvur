# Review, 2026-09-29: the goal against what `1.1.0` delivers

Written the day `1.1.0` shipped, at the owner's request: step back, judge the product
against its goal, and recommend by impact. The owner accepted every recommendation and
asked for a task list that runs unattended; it is Phases R9 to R15 of
[`tasks.md`](../../.kiro/specs/valvur/tasks.md). Evidence is cited by file; the figures
are the acceptance records' and the corpus's.

**The goal**, from `CLAUDE.md`: from an agent session, one request scans the project
and writes a report into it that is fast, complete or honest about why not, and
trustworthy. Locally. The market gap it fills is the Snyk CLI's, without the network.

## 1. Verdict

The goal is met on four of its five words. One agent request scans (MCP, ten clients,
eight of eight acceptance repositories reported correctly after the rule-ID decision);
nothing leaves the machine, provably; application repositories scan warm in 3.4 to
18 s on Linux; every surface says what did not run. **Trustworthy is the gap:** the
code-level detection is eleven rules, the threat data a scan uses can be a week or a
month old, and no precision or recall figure exists for any Scanner or finding class.

## 2. How the definitions are updated, as built

| data | upstream | refreshed by | oldest a scan uses |
|---|---|---|---|
| Trivy's database | daily | a scan, past 7 days (`api.py` `_ensure_data`); `valvur update` | 7 days |
| OSV's databases, with the `MAL-` entries | continuously | a scan, past 7 days by file time | 7 days |
| Name Index | daily, by `index.yml` | a scan, past **30** days | 30 days |
| CISA KEV | about daily | `valvur update` only, **never a scan**; the package's snapshot is catalog 2026.08.27 | unbounded |
| FIRST EPSS | daily | a per-CVE API call, on `full` only | none on `offline` |
| Gitleaks, Opengrep, Checkov and zizmor rules | per release | a valvur release | the installed version's |

Four defects in that table:

1. **KEV's age is the file's time** (`enrichment.py`, `_load_kev`). A package installed
   on 2026-09-26 reported the 2026-08-27 catalog as three days old; its 30-day
   staleness can never fire. F6.11 forbade exactly this for the database.
2. **A name absent from a 30-day-old index is reported at high as "almost certainly
   hallucinated"** (`dependency_reality.py`). A package published after the index was
   built, common for new AI SDKs, tells an agent to delete a real dependency. The index
   is published daily and costs 36 MB to fetch.
3. **Malicious-package data can be 7 days old**, and the attack runs at `npm install`,
   before any scan reads the manifest.
4. **Detection rules move only with releases**, about ten manual steps for one maintainer
   (`docs/RELEASING.md`).

## 3. Findings by area

**Build.** Digest pins, hash locks, a reproducible-build check, native multi-arch and the
pin test are sound. Drag: 125,157 lines of tests for 17,169 of source; the whole suite
took 718 s on this Mac; wall-clock asserts fail under swap (container ceiling 73 s
against 60, budget and doctor parity once each). The README says every commit is tested
on both runtimes on amd64 and arm64; e2e and Podman run on amd64 only, and arm64 scans
with the last published image.

**Deploy.** Stage, validate, brake, promote, with rehearsals, signing and provenance, is
sound. Drag: the manual steps and a bus factor of one (`MAINTAINERS.md`). The quick start
never says a container runtime is needed. `docs/examples/github-actions.yml` caches
nothing, so every run fetches 160 to 400 MB.

**Functionality.** The AI-specific Checks are the differentiator and are well built.
Gaps: static analysis is 11 Opengrep rules, whose taint rules have never fired on real
code and whose 11 non-pinning findings on eleven real repositories a reviewer accepted
none of (task 22.E.2); no check before a package is installed; private npm scopes and
Python indexes are not recognised, so internal packages read as hallucinated at high.

**Architecture.** The sealed container, the Snapshot, one egress module and per-class
identity are right and stay. Nothing is reused between scans: OSV-Scanner loads npm's
217 MB database, about 10 s, on every scan, lockfiles changed or not. Checkov's secrets
framework reports the same flood Gitleaks does, and a secret's fingerprint includes its
rule, so the two cannot merge: 7,640 findings for one planted flood (`r5.md`).

**Performance and accuracy.** Warm scans suit an end-of-task check, not every edit.
Ground truth is 22 planted expectations; the 13-repository corpus judges valvur's own
behaviour and never whether a finding is real; the AI Checks' recall on real code is
unmeasured. On `offline`, the default, ranking has no EPSS (`enrichment.py`), and KEV
matched 1 of 269 application CVEs (`EVALUATING.md`), so the default ranking is mostly
severity and the development-dependency demotion. A failed Scanner with nothing found
still reads `clean` (`tasks.md` §8 backlog).

## 4. Recommendations, by impact, as accepted

1. **Fresh data, and ranking that works offline.** KEV's age from its catalog and KEV
   refreshed by a scan; the index refreshed past 2 days; EPSS from FIRST's daily file,
   which also stops `full` sending CVE identifiers; the `MAL-` names published daily
   beside the index. R11.
2. **`check_package`**, answering offline before an install whether a package exists, is
   one edit from a popular name, or is known-malicious. R12.
3. **A labelled benchmark, then static analysis widened against it.** R9 and R13.
4. **The false positives enterprises see first**: private registries. R10.
5. **Trust fixes**: `inconclusive` for a failed Scanner with nothing found; Checkov
   without its secrets framework; the README's claims. R10.
6. **Reuse what cannot have changed.** R14.
7. **Less release drag.** R15.

Not recommended: reachability, Scanners for their own sake, a container-less mode on
macOS, or revisiting the `offline` default.

## 5. The evaluation, chosen

Exploit benchmarks (SecBench.js, BaxBench, CyberGym) score exploits run against live
code: dynamic testing, which valvur refuses (`CLAUDE.md` §2). The well-known static
scorecard is the OWASP Benchmark's: true-positive rate minus false-positive rate per
vulnerability category. Its Python edition has 1,230 cases, 530 real, in 14 categories
(`expectedresults-0.1.csv`), under GPL-3.0, so it is fetched at a pinned commit and
never vendored. No such benchmark exists for the other finding classes, so valvur
writes its own, vulnerable and safe twins scored by the same formula (ADR-0026, from
R9.2). The largest public list of hallucinated package names, 205,474 from Spracklen et
al. (USENIX Security 2025), is withheld by its authors to prevent attacks, so the
package-reality track generates its own.
