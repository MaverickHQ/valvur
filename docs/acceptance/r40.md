# Phase R40, the README on PyPI: the record

Built in a local session on 2026-10-09, after R39 landed, at the owner's word (D79). PyPI
renders the README as the project's description and resolves nothing relative. R40 has
the build write PyPI's copy, and `1.5.1` publishes it.

## Before and after

| | `1.5.0` on PyPI | R40's built description |
|---|---|---|
| images | 4, the demo not loading (the proxy was handed `docs/demo.svg`) | 7, each absolute: the logo, five badges and the demo |
| links | 52, 22 relative and leading nowhere | 55, none relative; into the repository at `v<version>` |
| `<picture>` | none then | its light `<img>`, since PyPI's page is light |

`1.5.0` was read in the browser pane, since PyPI answers scripts with a client
challenge. The built description was rendered with `readme-renderer[md]`, the library
PyPI uses, which kept every image and link and the centred layout.

## How it is held

- `test_pypi_readme.py` builds a wheel and reads its metadata: no relative link or
  image; every link into the repository at the declared version's tag, and naming a file
  that exists; the `<picture>` gone; GitHub's README still relative.
- `hatch_build.py` is release machinery, so `1.5.1`'s rehearsal runs the whole pipeline,
  and its TestPyPI upload runs `twine check` over the description.
- The local gate: 2,226 tests. Nothing in detection changed, so the Score was not run.
