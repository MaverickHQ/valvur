# Phase R50, an existing codebase adopts the gate: the record

Built on 2026-11-23 by the executor on the owner's Mac, with the image, the container tests,
the acceptance set and the Score on the AWS dev machine (D82t). It is the third phase of
[signal and adoption](../../.kiro/specs/signal-and-adoption/), stacked on R49's branch,
which is itself waiting for the owner at its last task. R50 needs nothing that task will
change.

## What it built

- **R50.1:** measured first. Reading a tree with git's plumbing is as fast as a Snapshot
  from disk; at its default depth `actions/checkout` leaves nothing of the base; OpenVEX
  names no conventional path for a project's documents.
- **R50.2:** `valvur scan --ref REF --out DIR` scans a commit's tree, read with
  `rev-parse`, `ls-tree` and `cat-file --batch`. Nothing is checked out, nothing under
  `.git` changes, and the Workspace gains no Results Folder. The commit's own project
  file gives the excludes and the Suppressions, and the history pass stops at the commit.
- **R50.3:** `valvur gate --new-since REF` scans REF itself, into the cache, and fails only
  on Findings whose Fingerprint REF does not hold. No baseline file. Two Scan Runs that
  differ in image, Profile or data are not compared.
- **R50.4:** the pipeline example's second job, `docs/CI.md`, the action's change as
  MaverickHQ/valvur-action#1, and the gate run for real on valvur's own pull requests.
- **R50.5:** a project's own VEX, honoured only through a `[[vex]]` entry with an expiry.
- **R50.6:** ranking reads a `[[context]]` declaration, within a tier and never across one.
- **R50.7:** one dependency Finding lists every lockfile it was found through.

## What the container caught

- **A test's own data.** `gate --new-since` passed every test over the fake Gitleaks and
  failed its first run through the real one: the second key in the test held a `9`, which
  is no AWS key's alphabet, so Gitleaks rightly reported one secret. The same key made an
  absence check in `scan --ref`'s test prove nothing. Both are valid shapes now.
- **No git in the image.** A ref cannot be read there (ADR-0005), and the first message
  said the ref names no commit. It now says git is not on PATH, and the gate on new
  Findings is documented as running from the host shim, not from the image as a step.

## The proof

valvur's own pull request #309, run 45095008959, the self-scan job: the base branch's tip

gated on; 0 below the threshold; 12 suppressed"* and *gate: passed*.
