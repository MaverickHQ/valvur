## What shipped

- **No manifest under `tests/` reads as one** (R27.2). OSV-Scanner, run from the image
  over the checkout as Scorecard runs it, reads nothing under `tests/`.
  `scripts/fixtures.py` copies a fixture back with its real names, and every copy goes
  through it.
  - Checkov's python-ecdsa advisory (PYSEC-2026-1325, CVE-2024-23342) moved from
    `.security-scan.toml` into `osv-scanner.toml`, with the same reason and review date.
  - **Measured on the way:** valvur honours a project's own `osv-scanner.toml`, so its
    self-scan read the ignore and the old suppression went stale. One record is kept, and
    the question of how valvur should treat that file is the owner's (§8).
- **Opengrep's stage without a variable `FROM`** (R27.3). One stage downloads the
  platform's binary and checks it against that architecture's digest. The binary is the
  same, `1b474bf2…`, and the image is 452 bytes larger (0.00005%). The two suppressions
  for the old `ADD` and `FROM` went with them.
- **Fuzzing** (R27.4). `fuzz/` has four fuzzers:
  - the install commands the hook reads;
  - every lockfile reader;
  - the project file's readers;
  - the readers of `findings.json`.

  `.clusterfuzzlite/` builds them. `fuzz.yml` runs them for 5 minutes per pull request
  and an hour nightly.
  - **Locally under atheris:** 60 s per fuzzer found crashes in two targets, and reading
    beside them found their siblings, 17 inputs in all. Every one is fixed, with its input
    as a regression test and a seed. Afterwards 120 s each, about 970,000 executions,
    found nothing.
  - **ClusterFuzzLite's first run on the pull request** found two more:
    - a NUL in a `pip install -r` path;
    - a finding with no `fingerprint` key.

    It dropped both as *not reproducible*, because its 30 s reproduction timed out:
    instrumenting every loaded module took 10 s to start one input. Each fuzzer now
    instruments only valvur and the parsers that shape its input, and one input starts
    in 0.5 to 1 s. Both crashes are fixed, with tests and seeds. Afterwards 120 s each,
    about 1,050,000 executions, found nothing.
  - **The next CI run reproduced its find** and failed the job, as a crash should. The
    find was a finding with no `title` key. The reply now reads a finding's fields as
    the gate does, and a test drops each field in turn. The run after that is clean.
