## What the numbers say

- **Static analysis barely registers.**
  - The benchmark finds 37 of 71 weak hashes with no false positive.
  - The INFO sink inventory flags every `eval` and `exec`, vulnerable or not, so it
    nets zero on code injection.
  - Shell injection is caught 7 of 13 times and wrongly flagged 7 of 7.
  - JavaScript has no rule at all, and scores only because Gitleaks finds the
    hard-coded keys.
- **Secrets, 90.**
  - Gitleaks misses a private key committed in history (R10.9). *Corrected by R10.9:*
    the cause is not the diff's `+`, which the history writer strips. Every path's
    lines were one file, so the placeholder key block's pattern read on into the real
    key committed after it.
  - It flags a placeholder key block (R10.8).
- **Dependencies, 100.** Every advisory over a year old is found on its vulnerable
  version and not on its fixed one, in all seven ecosystems. Every `MAL-` package is
  found.
- **Package reality, 81.**
  - Private registries are read as hallucinations in pip, npm and Composer (R10).
  - Two malicious npm names are still registered, as security holders, so existence
    alone passes them (R11).
- **Agent configuration, 94.3.** A paraphrased injection and an exfiltration
  directive pass the patterns; none of the benign or real files is flagged.
- **Infrastructure, 95.** Checkov does not flag `public-read` on `aws_s3_bucket_acl`,
  the AWS provider's form since version 4.
- **Real-code precision, 4.0.** None of the 24 findings of valvur's own rules and
  Gitleaks on the thirteen corpus projects is one a maintainer would act on. One is
  valvur's own false positive: the licence-file Check reads a dual licence as a
  contradiction (R10.7).

## What the measurement changed

- **The benchmark holds 452 real cases, not 530.** The first version of the list read
  530 from a summary of the page; the pinned file says 452.
- **Track 8 is smoothed precision.** The corpus offered no true positive, so plain
  precision could not tell one false alarm from forty (ADR-0026, amended).
- **Two defects in the generated tracks, each fixed under a test:**
  - an invalid YAML workflow, whose safe twin passed for free;
  - a ranking fixture merged away. A dependency finding's identity has no path, so the
    same package and version in two lockfiles is one finding at one path. That is noted
    for the owner in `tasks.md` §8.
- **Three tasks added to R10 from the measurement:** a dual licence (R10.7), a
  placeholder key (R10.8), and a key in history (R10.9).
