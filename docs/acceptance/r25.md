# Phase R25, what the code rules find: the record

Built in a Claude Code cloud session (D61): the VM is the local lane, GitHub's runners
the Linux lane, and the Mac lane is **pending**, held in `tasks.md` §8 for one run over
the landed stack.

## What shipped

Twelve rules of valvur's own (D60), each with a vulnerable and a safe twin as a test,
and each shipped on D29's bar. GitLab's audited set had nothing eligible for these
categories (R25.1), so none is vendored.

- **Command and code injection by taint** (R25.2): `valvur.python.command-injection`
  and `valvur.python.code-injection`, from request data. `subprocess-shell-true` joins
  the sink inventory.
- **Python's web categories** (R25.3): `path-traversal`, `insecure-cookie`,
  `open-redirect` and `xml-external-entities`.
- **JavaScript** (R25.4), in `rules/javascript-security.yaml`: `sql-injection`,
  `command-injection`, `path-traversal` and `ssrf`, from what an Express or Fastify
  handler reads off its request.
- **Every rule's CWE reaches `findings.json` and SARIF** (R25.5), under a test.

## What is still missed

- Opengrep's taint loses a flow through a slice, a `match` statement or a
  `configparser` read, which the Benchmark uses often: most of path traversal's 38
  misses and code injection's 11.
- XSS, LDAP and XPath injection and trust boundaries still find nothing on track 1;
  XSS, prototype pollution, weak crypto and open redirects on track 2.
- Track 2 has four cases per type, so its 100s say little alone; the independent twins
  under `tests/` and the corpus's express and fastify, where none of the rules fires,
  are the rest of the evidence.
