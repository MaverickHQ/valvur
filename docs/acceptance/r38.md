# Phase R38, what a project's own ignores hide: the record

Built in a Claude Code cloud session (D61). R38 builds D77: a comment or an ignore file in
the scanned project never hides a finding silently. Its exit is every ignore D77 names
visible in the report; the Score on both lanes, with any movement recorded and explained;
and the acceptance set green on both lanes.

## Before: what each ignore hid

R38.1 planted one finding behind each ignore D77 names, beside a twin no ignore covers
(`tests/project_ignores.py`, built at runtime), and ran each pinned Scanner from the
project's root as a user would. Five of the seven hid their finding; `.gitleaksignore` and
`.trivyignore` hid nothing only because valvur ran their Scanners from a scratch directory.
The table is R38.1's STATUS in `tasks.md`.

## After: every Scanner runs with them off, and valvur names them

| ignore | Scanner | how it is turned off (R38.2) | named as (R38.3) |
|---|---|---|---|
| `nosemgrep`, `nosem`, `noopengrep` | Opengrep 1.29.0 | `--disable-nosem` | `inSource`, the comment's line |
| `gitleaks:allow` | Gitleaks 8.30.1 | `--ignore-gitleaks-allow` | `inSource`, the comment alone, never the secret |
| `.gitleaksignore` | Gitleaks 8.30.1 | `--gitleaks-ignore-path /dev/null` | `external`, the entry's line |
| `.gitleaks.toml` allowlists | Gitleaks 8.30.1 | a configuration valvur writes, through `GITLEAKS_CONFIG_TOML`, with the project's rules and no allowlist | `external`, the criterion: paths, commits, regexes or stopwords |
| `checkov:skip` | Checkov 3.3.19 | none exists; no `--quiet`, and its `skipped_checks` become findings titled *not evaluated* | `inSource`, with its reason |
| `.trivyignore` | Trivy 0.74.0 | `--ignorefile /dev/null` | `external`, with its `exp:` |
| `osv-scanner.toml` | OSV-Scanner 2.6.0 | `--config /dev/null` | `external`, with `reason` and `ignoreUntil` |

The e2e test (`tests/test_project_ignores_e2e.py`) scans the R38.1 project and finds all
seven, each named in `ignored_by` in `findings.json` and as a SARIF suppression that
validates against SARIF 2.1.0's schema.

**An ignore is a suppression only with a reason and an expiry** (R38.4). Of the seven, only
`osv-scanner.toml` can state both. An accepted one is suppressed until its expiry, inclusive
and UTC, as `.security-scan.toml`'s are; a lapsed one reports its finding again with a
`valvur.suppression.expired` finding on the ignore's file, which fails the gate at every
threshold. Every other ignore leaves its finding active, listed in `SUMMARY.md` under
*Ignored by the project, not accepted*.

## Found on the way

- **A stored result was reused across a change of arguments.** ADR-0030's reuse key held
  the Scanner, its version, the Profile, the dependency files and the data, not the
  arguments. OSV-Scanner's result from before `--config /dev/null` was reused after it, and
  the ignored advisory stayed hidden. The key now holds the argv (6f8a234).
- **valvur's own `.gitleaks.toml` hid ten findings.** It allowlists the AWS key its tests
  plant by `regexes`, which R38.3 had left unnamed, since a finding never carries the
  secret. The line is now matched instead (8a7a251). A Gitleaks allowlist cannot carry an
  expiry, so each file that plants the key is accepted in `.security-scan.toml` with a
  reason and 2027-09-14, the Checkov advisory's review date. Removing the literal from the
  tree would not clear it: the key is in the 200 commits history reads.

valvur's scan of itself, at R38's head on `valvur:dev`: `clean`, 12 suppressed, 0 active.
CVE-2024-23342 on `requirements-checkov.txt` is suppressed by `osv-scanner.toml`, its reason
and review date in the justification.
