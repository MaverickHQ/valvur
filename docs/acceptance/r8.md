   in the Scan Container's terms;

   image's own empty `/workspace`: an SBOM of 0 components against the host's 16;

   down (flags `0x80`, `0x1002`); only an interface with `IFF_UP` counts, and the default
   bridge's `eth0` reads `0x1003`.

## R8.2, the example as a pipeline step

`tests/test_pipeline_example.py` runs `docs/examples/github-actions.yml`'s three `run:`
blocks in order, with `GITHUB_WORKSPACE` a checkout of `app.py` and a pinned
`requirements.txt`, `RUNNER_TEMP` an empty directory and `VALVUR_IMAGE` the image baked
from this branch: fetch with a network (the database, KEV, the index, and OSV's PyPI
database, which `valvur update /src` now fetches for the checkout's lockfiles), scan
with `--network=none` into `/out`, gate. On this Mac, from an empty cache, 40.6 s for
the three, the run complete and the boundary *this job's container, with no network*.
The CI's e2e job runs the same test on Linux on every commit.

Before `update PATH`, OSV's databases were fetched only by a scan, since only a project
names its ecosystems; a scan under `--network=none` could not fetch them, OSV-Scanner
failed, and the gate failed the incomplete run.

The GitLab job (`docs/examples/gitlab-ci.yml`) is a documented shape: the image as the
job's container, GitLab's helper cloning the project. It has not been run here.

## R8.3, a mirror in the customer's own registry

`tests/test_customer_mirror.py`, on this Mac in 68 s. Two Docker networks, one ordinary
for the copy and one created `--internal`, with no route out, for the machine that
scans; a `registry:2`, pinned by digest, on both. Into it: the image, pushed blob by
blob from `docker save`'s OCI layout and read back through `valvur.oci` with the same
manifest digest; the vulnerability database and the name index, copied from
`mirror.gcr.io` and GHCR. On a file server on the internal network: KEV, and OSV's
database for PyPI. The image, run on the internal network with the mirror settings:
`valvur update /src` exit 0, then `valvur scan`, complete and `clean`, with
`what_left_the_machine: nothing` and nothing fetched during the scan. Nothing the test
started was left behind.

On Linux the daemon pulls the image back from the mirror and the scan runs that copy.
Docker Desktop's daemon cannot reach a registry published on the Mac's loopback, for a
push or a pull (measured: *connection refused* on `127.0.0.1`, a timeout on
`localhost`), so on the Mac the copy is verified by its digest and the scan runs the
local image with the same content.

The ECR steps in `docs/AIR-GAPPED.md` are a documented shape. valvur fetches the index,
KEV and OSV's databases anonymously and carries no AWS credentials, so in ECR the
image and the database live in the registry and the rest are files served inside the
account. The measured run in an AWS account is the owner's (`tasks.md` §8).
