Built on 2026-11-23 by the executor on the owner's Mac, with the container tests, the
acceptance set and the Score on the AWS dev machine (D82t). It is the fifth phase of
[signal and adoption](../../.kiro/specs/signal-and-adoption/), stacked on R51's branch.

## What it built

  rows are 1.0's: the release has evidence for every row of Build L2 and for neither row
  L3 adds. OpenVEX 0.2.0 requires at least one statement. The mutation score was in no

- **R52.2:** `scripts/image_vex.py` writes the release's OpenVEX document from the image

  justifications. valvur decides `not_affected` for nothing.
- **R52.4:** `SECURITY.md` says *SLSA Build L2, and no higher*, with a row of evidence for
  each requirement, held to `release.yml` by a test. `MAINTAINERS.md` says what happens if
  the one person who can release cannot.
- **R52.5:** the Health record. `scripts/health.py` and `health.yml` rewrite one issue
  daily from recorded runs, and `mutation.yml` now leaves its score in an artifact.

## What the measurements changed

- **A document with no statements is not OpenVEX,** so verdicts with nothing to say give no
  document, where the task had an empty one.
- **The Health record needs `actions: read`** beside `issues: write`: an artifact is not
  downloaded without a token, 401.
- **The design's sentence for `MAINTAINERS.md`,** *a security patch still releases itself*,
  is not true today: ADR-0032 is proposed and its workflows are not on `main`. The file
  says no release happens.
- **Three answers in `docs/BEST-PRACTICES.md` were stale** against the tree.
