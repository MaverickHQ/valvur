  in the corpus, each labelled.

only four of GitLab's permissively licensed rules met D29's bar.

## The rules (R13.1 to R13.3)

- **303 candidates, 106 eligible:** Bandit's 68 Python rules, gosec's 27 Go and ESLint's
  11 JavaScript and TypeScript (`tests/eval/sast-rules.json`). Java is out: its rules
  translate find-sec-bugs, LGPL-3.0.
- **Measured rule by rule** over the benchmark, the JavaScript twins and the corpus
  (`tests/eval/sast-rules-measured.json`). Four ship: Python's weak `random`, string-built
  SQL and unsafe `yaml.load`, and JavaScript's `eval` of an expression.
- **Three measurements corrected the list on the way.**
  1. Opengrep read `.semgrepignore` from its working directory, so the first per-rule
     run skipped every `tests/` tree, and `pickle` looked like it met the bar (0.57).
     Measured in the target, it is 0.43.
  2. GitLab's `subprocess` shell rule matched exactly the 14 benchmark lines valvur's
     own rule does, and doubled acceptance repositories 1 and 4's findings. D29's bar
     now requires a true positive at a line valvur does not already report.
  3. The SQL rule and valvur's own `string-built-sql` both report an inline f-string
     query. The two are one finding now, at the worse severity. The SQL rule stays,
     for the queries it follows through a variable.
