# Phase R23, the host side in layers: the record

Built in a Claude Code cloud session (D61): the VM is the local lane, GitHub's runners the
Linux lane, and the Mac lane is **pending**, held in `tasks.md` §8 for one run over the
landed stack before the next release.

## What shipped

- **Four layers, checked** (R23.2). `core` < `infra` < `app` < `surfaces`, each importing
  only from those below. `scripts/layers.toml` assigns all 115 modules, and
  `scripts/check_layers.py` holds the direction and the absence of cycles in `verify.sh`,
  deferred imports and each package's `__init__` counted. The baseline is empty. `mypy
  --strict` passes on `core`, as the gate's `strict` check.
- **The package loads only what is asked** (R23.3). `import valvur` loads nothing else;
  `import valvur.hook` loads 9 of valvur's modules, 52 before.
- **One scan service** (R23.4). The CLI and the MCP `scan` tool both scan through
  `service.run_scan`; `operations` and `reply` reach nothing in the MCP surface; a
  `scan_cancel` sent before its scan's job exists stops that scan.
- **Each concept once** (R23.5, R23.6). One datasets table for every refresh and
  inconclusive threshold (`update --if-stale` now refreshes what a scan would, KEV and
  EPSS included); one predicate for an active Finding; the network grant is
  `Invocation.network` alone; one parse of the project file and one File Set per scan;
  one flag builder for both launchers.
- **Typed messages** (R23.7). A scan's events carry a kind and fields, and the reply
  reads kinds; `Runtime` and `ScannerAdapter` declare every member `app` uses.
- **The four lapses** (R23.8). `/tmp` is `noexec` for every tool and Opengrep runs from
  the tree the image unpacked; `full` in the image asks the registry, tested through a
  stand-in; `VALVUR_CACHE` wins over `XDG_CACHE_HOME`; one Scanner list; dead code and
  duplicated constants gone.
- **The orchestrator, small** (R23.9). `api.py` is 185 lines (1,245); no `app` function is
  over 80; no import cycle; 62 deferred imports (229), each with its reason, listed in
  `tests/fixtures/deferred-imports.txt`.

- **The gate** (`scripts/verify.sh`): all seven checks pass at `4c2b3d2`; the unit run is
  1,879 passed, 7 skipped.
- **The e2e run on the VM,** on the image built at `313a2fa`: 52 passed, 6 failed, 7
  skipped, once the one real failure was fixed.
  - **Fixed at this exit:** `test_cancel_stops_the_queue` still called
    `operations.start_scan`, which R23.4 removed and no unit run reaches. It starts its
    scan as the MCP tool does now, and passes against the image.
  - **Cloud-only (D61i), each a network or certificate error inside a container:**
    `test_constraints_budgets` (both tests), `test_constraints_canary`,
    `test_exclude_means_one_thing` and `test_two_scan_containers`, each a `full` scan whose
    dependency-reality reached no registry; and `test_pipeline_example`, whose
    `valvur update` in the image met the session's TLS certificate. CI's e2e on this
    phase's PR runs them: CI_E2E.
- **Timing tests on the VM:** two fail here and on `main` alike,
  `test_engine.py::test_a_tool_past_its_timeout_is_killed_with_its_whole_group` and
  `test_one_deadline.py::test_past_its_grace_the_host_kills_the_engine_and_everything_it_started`.
  The VM's PID 1 (`process_api`) reaps no orphan, so a killed grandchild stays a zombie
  that `kill(pid, 0)` still finds. Not R23's; the Mac and CI judge them.
