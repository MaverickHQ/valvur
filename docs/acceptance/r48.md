# Phase R48, the measurement for every rule and every Scanner: the record

Built on 2026-11-22 by the executor on the owner's Mac, with the image, the container tests,
the acceptance set and the Score on the AWS dev machine (D82t). It is the first phase of
[signal and adoption](../../.kiro/specs/signal-and-adoption/), stacked on R46's branch.
Nothing valvur reports changed in this phase: it is the measurement R49's bar is set from,
and three guards on the build's own honesty.

## What it built

- **R48.1:** measured first. On the corpus of 48 projects Checkov gives 74 Findings in 10
  rules and zizmor 702 in 12, four of them with more than 25.
- **R48.2:** the real-code track's report gains `by_rule` and `by_scanner`, and `--jobs N`
  scans N projects at a time, with one report at any N.
- **R48.3:** Checkov's and zizmor's Findings are judged in a table of their own, `hygiene`,
  never pooled into the track. 241 labels, each read against its file at the project's
  pinned commit. The baseline records every label's verdict, so one that changes needs a
  reason.
- **R48.4:** `docs/RULES.md` gains a second table: every other rule that fired on the
  corpus, with its counts on maintained code apart from its counts on planted cases.
- **R48.5:** the mutation check no longer counts a hunk that only changes an annotation.
- **R48.6:** no test, script or workflow compares against a moving target. The licence
  check reads the base, digest included, from the Dockerfile.
- **R48.7:** the hostile fixtures are stored as `<name>.fixture`, so no agent working in
  the repository loads them as its own.

The readings behind these are at the head of `tests/eval/labels/hygiene.toml`, for the
owner to overrule. A sampled rule is judged on the 25 Findings with the lowest
Fingerprints, a draw across Findings and not across projects.
