# Phase R26, a lighter release: the record

Built in a Claude Code cloud session (D61). R26 changes how a release runs, not what a
scan finds, so its exit is a rehearsal of the new flow measured against `1.4.0`'s, the
owner's actions counted, CI, and the Score unchanged.

## What shipped

- **Rehearse when the machinery changed** (R26.2, D62a). `prepare_release.py` names each
  file `release.yml` builds from that changed since the last tag, or says none did. A
  test finds that list by reading the workflow, the bake file, the Dockerfile and
  `pyproject.toml`. On this branch it names `release.yml` (R19's runners), so `1.5.0` is
  rehearsed.
- **The tag's run trusts CI's verdict** (R26.3, D62b). `scripts/ci_verdict.py` reads the
  eight required checks on the tagged commit. `verify` reruns `verify.sh` and the whole
  suite only when the verdict cannot be read. The tag's signature, `main`, the version,
  the licence check, the self-scan and the Score are unchanged.
- **No closing pull request** (R26.4, D62c). The README's status line names the version
  alone and a PyPI badge says what is published. `--published`, `published.yml` and their
  tests are gone.
- **Local pre-checks only where CI cannot reach** (R26.5, D62d): the self-scan on the
  day's data, and the Mac lane when detection changed.

**What the rehearsals found:**

1. **A real bug, fixed on this branch.** Run 37210754192's `artifact` failed on amd64 in
   `test_a_running_scan_container_has_no_mount_of_the_source_tree`, with nothing in the
   log to say why. The test now records what the run returned, and it said 1.
   - **The cause:** a Snapshot past `TMPFS_LIMIT` lands in a named volume. Docker's
     classic store initialises that volume from the image's `/workspace`, which `WORKDIR`
     under `USER 10001` made 10001's and 755. The scan runs as the invoking user with every
     capability dropped, so the engine could not write the first file
     (`PermissionError: '/workspace/app.py'`, reproduced on the VM).
   - **Why only one runner failed:** runners whose Docker uses the containerd store
     passed, which is why CI and the arm64 leg did.
   - **The fix:** `/workspace` is 1777, as the in-memory landing always was, held by
     `test_workspace_landing.py` (Dockerfile and image).
   - It reached users: a project whose Snapshot passed 512 MiB could not be scanned on
     such a host.
2. **A test that failed every weekend, fixed.** `test_customer_mirror.py` asserted that a
   scan fetched nothing. ADR-0027 ages KEV by its catalog's release date and refreshes it
   past two days. On 2026-10-04 at 15:19 UTC, CISA's newest catalog (released Friday)
   passed two days. Every scan from then on fetched KEV again, from the customer's own
   file server. The test now asserts that every fetch comes from the customer's servers.
3. **The freshness gate's weekend, for the owner.** For the same reason, run
   37215618801's Score held at 73.9 on every track, but the freshness gate failed:
   `stale: kev 2.04 days (over 2)`. No copy of KEV anywhere was younger. The gate measures
   CISA's release cadence as well as valvur's freshness, and it fails any Score run, a
   release's `verify` among them, from Friday afternoon to CISA's next release. §8 holds
   the decision, with a proposal. An end-to-end rehearsal waits for CISA's next catalog.
