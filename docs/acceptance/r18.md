# Phase R18, the install asks first: the record

## What shipped

- **`valvur.installs`** reads the packages an install command would install: npm, pnpm,
  yarn, bun, pip, uv, poetry, cargo, gem and composer, and `-r` files. It never takes a
  path, URL or git reference for a name, and reads a chain one command at a time.
- **`valvur-hook`** reads Claude Code's `PreToolUse` event. When a package is flagged, or
  cannot be checked for want of an index, it answers `ask` with each verdict; otherwise
  it says nothing. It never denies, never runs the command and opens no socket.
  Against the real index, 4.4 million npm names, it answers 50 names in 0.16 to 0.30 s.
- **The plugin's hook.** `hooks/hooks.json` runs `hooks/pre-tool-use.sh`, which starts
  valvur only when the command names an installer: the pinned `uvx` command costs about
  0.45 s warm, too much before every shell command. `claude plugin validate --strict`
  passes, and the pin moves with the release.
- **Kiro** gets no hook: its hooks can only allow or block, and powers cannot carry them
  (D44's fallback). The skill's rule stands alone there.

## The smoke run (D46)

`scripts/acceptance/hook_smoke.py`: `claude -p` with the plugin, the `Bash` tool allowed,
every installer, `curl` and `wget` a recording stub first on `PATH`, asked to install a
made-up npm package in an empty scratch directory.

- **The hook stopped the install.** Under `-p`, Claude Code turns the hook's `ask` into a
  `permission_denied` with `decision_reason_type: "hook"` and the hook's reason; the
  model received the reason and reported it. The hook documentation does not say this.
- **Nothing was installed:** the stubs recorded no install of the name.
- **Two runs:** the exploratory one, $0.69, and the script's, $0.38. D46 stands at $1.07
  of $5.

## Released in 1.3.0, 2026-10-03

1.3.0 ships R17 and R18. It was prepared by `scripts/prepare_release.py 1.3.0`, one commit of
15 files with the hook's pin among them, plus `docs: the 1.3.0 entry` (#177).

- **Checked before the rehearsal:** the release's own self-scan gate, run locally against a
  database refreshed that day (0.1 days old): `scan . --profile full`, then `gate --fail-on
  any --no-inconclusive`. No finding at any severity, 4 suppressed. This gate had stopped
  1.2.0, so it now runs first. The Mac's Score on the 1.3.0 image is 64.9, every track at
  its baseline.
- **The rehearsal,** run 37064312498 on `release/1.3.0` at `deddb29`: green to the brake in
  30 minutes, cancelled there.
- **The release run,** 37114041722 on the tag at `deddb29`. The tag push was at 09:44 UTC and
  `latest` moved at 10:16:48: 32 minutes, about 2 at the brake.
- **Verified from outside:**
  - PyPI serves 1.3.0, a wheel and an sdist.
  - `ghcr.io/maverickhq/valvur:1.3.0` and `:latest` are one image, for amd64 and arm64.
  - The cosign signature and the SLSA attestation verify.
  - No Dependabot alert is open.

**The plugin as shipped, from PyPI's 1.3.0:**
- **Tools** (`plugin_smoke.py`): the plugin loaded at 1.3.0, the skill is listed, and the
  server connected with all seven tools ($0.69).
- **The hook** (`hook_smoke.py --as-shipped`). It took three runs to see clearly.
  1. **The first run failed.** `uvx --from valvur==1.3.0` could not resolve the release:
     this machine's `uv` had cached PyPI's index for `valvur` from before it. The hook's
     command failed, Claude Code treats a failing hook as non-blocking, and the install
     reached the stub `npm` unasked. **Fixed in the plugin's script**, which now answers
     `ask` naming why the check did not run (`fix(r18)`, a test for it). It reaches
     plugin users with the plugin's next version.
  2. **The second scripted run, after `uvx --refresh-package valvur`, was inconclusive.**
     The agent never ran the install. As shipped, the skill has it call `check_package`
     first, and an agent that does sees the package is nonexistent. The judge now tells
     that apart from a failure.
  3. **A run with the stream kept passed:** the agent ran `npm install`, the hook from
     PyPI's 1.3.0 stopped it with its verdict, and nothing was installed.
- **Agent runs:** D36 stands at $7.20 of $10, and D46 at $3.32 of $5.

## Released in 1.3.1, 2026-10-03

1.3.1 ships one fix: when valvur cannot start, the plugin's hook asks rather than letting
the install through. Its version is 1.3.1, so `/plugin update` brings it (#179).

- **Pre-check:** the self-scan gate on data 0.7 days old: no finding at any severity, 4
  suppressed.
- **The rehearsal,** run 37117644918 at `649bedd`: green to the brake, and cancelled there.
- **The release run,** 37119311574 on the tag at `649bedd`. The tag push was at 11:19 UTC,
  `verify` passed at 11:39, the artifacts at 11:50, and `latest` moved at 11:57:02. That is
  38 minutes, 6 of them at the brake.
- **Verified from outside:**
  - PyPI serves 1.3.1, a wheel and an sdist with provenance.
  - `ghcr.io/maverickhq/valvur:1.3.1` and `:latest` are one image, for amd64 and arm64.
  - The cosign signature and the SLSA attestation verify.
  - No Dependabot alert is open.
- **PyPI's index lags an upload.** Just after promote, the version's own endpoint answered
  200 and the simple index listed 1.3.1, but PyPI's project page and `uv` did not see it.
  `uv` resolved it about a minute later. 1.3.0's first as-shipped run failing to resolve its
  release was most likely this same lag, more than this machine's cache.

**The plugin as shipped, from PyPI's 1.3.1:**
- **Tools:** the plugin loaded at 1.3.1, the skill is listed, and the server connected with
  all seven tools ($0.69).
- **The hook, verified directly.** The plugin's own `pre-tool-use.sh`, run with PyPI's 1.3.1
  under the smoke run's `PATH`, with every installer a stub ahead of `uvx`, answers `ask` for
  the made-up package with its verdict. Nothing reaches a stub.
- **The hook through an agent:** two runs, neither able to show it, and both instructive.
  - The first agent ran `valvur check npm <name>` through `Bash`, which names the package and
    installs nothing. The judge had counted that as an attempt; now only an install of the
    name counts (a test holds it).
  - The second followed the skill: `check_package` first, refused under `-p`, then
    `valvur check`, and it never ran the install. The judge reports such a run as
    *inconclusive*.
  - As shipped, then, agents check before they install, as the skill asks, and the hook is
    the backstop. It was proved stopping an agent's install in 1.3.0's as-shipped run.
- **Agent runs:** D36 stands at $7.89 of $10. D46 is at $4.50 of $5, so no further agent
  run is made under it.
