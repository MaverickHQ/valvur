# The fourth review — a level-400 analysis of `main` at `2287dc7`

> Written 2026-09-23, the day after Phase 27 closed. Every number below came from
> the tree, the workflows, the GitHub API or a run log that day, not from memory;
> where a thing could not be measured, it says so. Twenty-four actionable findings
> and two informational rows; the tasks are **Phase 28** in
> [`tasks.md`](../.kiro/specs/valvur/tasks.md), which is authoritative for what
> happens to each. The third review's list, with its own verdicts, is
> [`OPEN-ITEMS.md`](OPEN-ITEMS.md).

**The one-paragraph verdict.** The product's constraints are enforced, not aspired
to: the moat is a test, the results contract is a generation, the supply chain is
pinned to the digest, and every claim in the plan carries a measurement. What this
review found is not correctness in a scan — the corpus and 1,059 tests hold that —
but **the edges of the trust boundary being wider than the artifacts suggest**
(Deploy), **GitHub's own security features switched off on a security tool's
repository** (Operations), **Checkov being the product's latency** (Functionality),
and **a handful of things the previous day's refactors left behind** (Architecture
— one of them the reviewer's own).

None of the twenty-four changes what a scan reports. Three of them — D1, O1, F3 —
change what an attacker can do, which is the lens this product asks to be judged
by.
